# 테스트 계획

## 1. 목표

설정 검증, 수집 결과 처리, LLM 응답, 날짜별 저장, cron용 실행 계약을 외부 네트워크와 실제 API 비용 없이 검증할 수 있어야 한다. 네트워크 및 LLM 의존성은 테스트에서 mock 또는 fixture로 대체한다.

## 2. 테스트 수준

### 단위 테스트

- `.env` 필수 키, 기본값, 정수 범위, 언어 수준, URL 및 JSON 출처 목록 검증
- URL 정규화, 중복 판정, 제목 slug 및 해시 파일명 생성
- 시간대 경계에서 날짜 폴더 계산
- 뉴스 묶음 프롬프트 렌더링, 미정 변수 및 전체 입력 길이 제한
- 일일 통합 자료의 단어 수, 섹션, 출처 링크 및 학습 시간 표시 검증
- LLM 응답 섹션 검증과 예외 마스킹
- 요약 JSON 필드 및 종료 코드 결정

### 통합 테스트

- 로컬 HTTP mock 서버의 정상 RSS/API 응답, 빈 목록, 잘못된 데이터 처리
- 429/5xx 이후 재시도, 연결 타임아웃, `Retry-After` 적용
- OpenAI 호환 API mock 정상 응답, 인증 실패, malformed 응답 처리
- 임시 디렉터리에 날짜 폴더, 선택 언어 이름의 Markdown 한 개, `run-summary.json` 생성 및 원자적 저장
- 같은 날짜·언어 반복 실행에서 자료 기본 건너뜀과 `--force` 재생성
- 한 출처 실패 후 다른 출처 뉴스까지 포함한 통합 자료 생성 및 부분 성공 종료 코드

### 수용 테스트

- 샘플 `.env`와 mock 제공자로 `./run.sh`의 비대화형 실행을 완료한다.
- 영어 및 프랑스어, 서로 다른 수준 설정이 자료 메타데이터와 프롬프트 입력에 반영된다.
- `--debug` 로그에서 진단 정보가 증가하고 테스트 API 키는 어떤 출력에도 존재하지 않는다.
- 존재하지 않는 프롬프트, 잘못된 URL, 출력 불가 경로에서 기대 종료 코드와 명확한 오류를 확인한다.
- cron과 유사한 최소 환경 변수 및 작업 디렉터리 조건에서 실행한다.

## 4. 콘텐츠 및 보안 점검

- 기사 입력의 명령형 문구가 프롬프트 지시를 덮어쓰지 않는 테스트를 둔다.
- 원문을 장문 그대로 복사하는 응답을 완벽히 자동 판정하기 어렵다는 한계를 기록하고, 알려진 장문 복제 fixture를 검출하는 회귀 검사를 둔다.
- 로그와 JSON 산출물 전체를 테스트 API 키 문자열로 검색해 노출이 없는지 확인한다.
- URL, 제목, 기사 본문에 경로 조작 문자열이 있어도 결과 파일이 출력 루트 밖에 생성되지 않음을 확인한다.
- 사이트별 수집기 테스트 fixture는 저장 및 재배포 권한이 확인된 최소 공개 예시만 사용한다.

## 5. 완료 기준

- 자동 테스트 전부 통과
- 네트워크 의존 테스트는 mock으로 재현 가능
- CLI 종료 코드와 설정·출력 계약 테스트 완료
- 비밀값 노출 검사 통과
- 프롬프트 변경 시 영어·프랑스어 및 복수 뉴스 통합 fixture 테스트 통과
- 수집 뉴스 수와 무관하게 일일 학습자료는 최대 한 개이며, 지정한 읽기 분량 검사를 통과
- 실제 사이트 smoke test는 운영 전 선택적으로 수행하고, 사이트 차단이나 약관 위반을 우회하지 않음

초기 Python 구현의 테스트 도구는 표준 `unittest` 또는 저장소에서 선택한 테스트 프레임워크로 확정한다. 이 문서는 특정 테스트 러너를 강제하지 않는다.
