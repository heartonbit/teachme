# 개발 계획

## 1. 구현 단계

### 단계 1: 실행 기반과 설정

- 프로젝트 구조, `run.sh`, Python 패키지 진입점 구성
- `.env.example`, 비밀 제외 규칙, 설정 로더 및 사전 검증
- CLI 옵션 `--debug`, `--date`, `--force`, 종료 코드 구현
- 설정·CLI 단위 테스트

**완료 조건:** 잘못된 설정이 네트워크 요청 없이 진단 가능한 오류로 종료되고 cron 진입점이 인자를 그대로 전달한다.

### 단계 2: 뉴스 수집

- 공통 뉴스 후보 데이터 모델 정의
- RSS/공식 API 수집 인터페이스와 정규화 구현
- 기본 미디어별 공개 수집 방식 조사 및 사이트별 어댑터 구현
- 타임아웃, 제한 재시도, 중복 제거 및 fixture 테스트

**완료 조건:** 수집된 후보에 출처 URL과 매체 ID가 있으며, 출처별 실패가 나머지 수집을 중단하지 않는다. 기본 URL에서 사용할 수 있는 피드가 확인되지 않은 출처는 HTML 탐색 방식과 정책을 별도로 승인한다.

### 단계 3: LLM 및 프롬프트

- OpenAI 호환 API 어댑터와 뉴스 묶음 단위 네트워크 mock 테스트
- 외부 파일 프롬프트 로더 및 변수 검증
- 언어·CEFR 입력, 전체 입력 길이 및 응답 검증, 토큰/요청 제한
- 여러 뉴스를 하나의 짧은 일일 다이제스트로 통합한 Markdown 생성

**완료 조건:** 영어·프랑스어와 여러 수준을 시험하고, Reading 250-350단어 및 전체 3-5분 목표를 검증하며, malformed 응답은 저장하지 않는다.

### 단계 4: 산출물과 실행 요약

- 선택한 언어명의 Markdown 파일, 날짜/시간대 계산, 원자적 쓰기 구현
- 해당 날짜·언어 자료 건너뜀 및 `--force` 동작
- `run-summary.json`의 수집 통계, 단일 생성 건수(0 또는 1), 출처별 결과 및 종료 코드 확정
- 출력 실패, 부분 성공, 재실행 통합 테스트

**완료 조건:** 수용 테스트의 디렉터리·파일 계약, 짧은 학습 분량, 통합 요약 및 부분 실패 동작을 충족한다.

### 단계 5: 운영 검증

- cron 최소 환경 테스트와 설치 절차 검증
- 비밀값 로그 검사, 문서와 실제 CLI 도움말 일치 확인
- 기본 미디어 각 어댑터의 공개 접근 smoke test
- 운영 시각, 보존 기간, 알림, 동시 실행 잠금 여부 확정

**완료 조건:** cron 실행 결과를 운영자가 요약 파일과 종료 코드로 판정할 수 있다.

## 2. 권장 작업 순서 및 의존 관계

설정/CLI 계약을 먼저 고정하고, 공통 후보 모델과 수집 인터페이스를 정의한 뒤 LLM 생성 및 출력 저장을 연결한다. 실제 뉴스 사이트 연결과 독립적으로 mock 기반 end-to-end 흐름을 먼저 완성하면 사이트별 변동이 핵심 파이프라인을 막지 않는다.

## 3. 주요 구현 산출물

- 실행 가능한 셸 진입점과 Python 패키지
- `.env.example`, `.gitignore`, 의존성 정의 파일
- 외부 프롬프트 파일
- 기본 미디어 수집 어댑터와 mock/fixture 테스트
- 날짜별 언어 선택 통합 학습자료 파일 및 실행 요약 생성기
- 테스트 스위트와 이 문서 묶음의 실제 동작 기준 갱신

## 4. 완료 정의

- 필수 테스트가 지원 환경에서 통과한다.
- `.env` 비밀값이 Git, 로그, 산출물에 포함되지 않는다.
- CLI 도움말, 종료 코드, 환경 변수 설명이 문서와 일치한다.
- cron과 동등한 비대화형 실행을 검증했다.
- 각 기본 미디어의 실제 수집 방식, 공개 접근 가능 여부 및 제한 사항이 기록돼 있다.
- 부분 실패, 재실행, 날짜 경계가 테스트됐다.
- 알려진 제한과 운영 결정 항목이 완료 전에 정리되거나 소유자에게 명시적으로 이관됐다.
