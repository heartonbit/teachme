# 운영 가이드

## 1. 사전 조건

- Linux 호스트와 POSIX 호환 셸
- Python 3.10 이상
- OpenAI 호환 API의 기본 URL, API 키, 모델 ID
- `.env`에 설정된 공개 뉴스 URL의 접근 가능 여부
- 결과를 저장할 디스크 공간 및 `result/` 쓰기 권한

런타임 및 테스트는 Python 표준 라이브러리만 사용하므로 추가 패키지 설치가 필요 없다.

## 2. 최초 설정

1. 저장소 루트에서 `./install.sh`를 실행한다. 이 명령은 `.env`를 기존 값이 없을 때만 생성하고, `result/`, `logs/`와 실행 권한을 준비한다.
2. `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`을 설정한다.
3. `NEWS_SOURCES_JSON`, `TIMEZONE`을 확인한다. 언어와 CEFR 수준은 실행 때 `--language`, `--level`로 지정한다.
4. 추가 패키지 설치 없이 `./run.sh --language English --level B1 --debug`로 수동 시험 실행한다.
5. 생성된 `result/YYYY-MM-DD/English.md`의 언어·수준 메타데이터, 출처 링크, 분량 및 `run-summary.json`을 확인한다.
6. `.env`와 API 키가 버전 관리에 포함되지 않았는지 확인한다.

## 3. 수동 실행

```sh
./run.sh --language English --level B1
./run.sh --language French --level A2 --debug
./run.sh --language French --level A2 --date 2026-10-05
```

실제 실행 날짜 예시는 실행 시점에 맞게 바꾼다. 재생성이 필요한 경우에만 `--force`를 사용한다.

## 4. cron 설정 예시

cron은 셸 초기화 파일을 읽지 않는 경우가 많으므로 절대 경로를 사용하고, 스크립트가 프로젝트 루트로 이동하는지 확인한다. 아래는 매일 06:30에 실행하는 예시다.

```cron
30 6 * * * /absolute/path/to/teachme/run.sh --language English --level B1 >> /absolute/path/to/teachme/logs/cron.log 2>&1
```

설치 시 확인 사항:

- 실행 계정이 `.env`를 읽고 출력 디렉터리에 쓸 수 있어야 한다.
- `NEWS_SOURCES_JSON`의 URL은 RSS/Atom 피드이거나 HTML에서 공개 RSS/Atom 대체 링크를 제공해야 한다. 이 버전은 기사 목록 HTML을 직접 수집하지 않는다.
- cron의 `PATH`는 제한적이므로 셸 스크립트가 실행 파일 위치를 명시하거나 PATH를 설정해야 한다.
- 서버 시간대와 `TIMEZONE`의 차이를 확인해 실행 시각과 결과 날짜를 의도대로 맞춘다.
- `logs/` 경로를 준비하고 logrotate 등으로 로그 보존을 관리한다.
- 중복 실행을 막아야 하는 배포에서는 `flock` 등 잠금 적용을 검토한다. 잠금은 병렬 실행 가능성을 확인한 뒤 구현한다.
- cron이 실패 종료 코드를 알림에 활용하도록 명령 끝에서 `run.sh`의 종료 코드를 보존한다.

## 5. 로그 및 산출물 점검

- 기본 모니터링: cron 로그의 실행 시작/종료, 처리 건수, 종료 코드
- 상세 조사: `./run.sh --language English --level B1 --debug`로 재현하되, 로그 공유 전 개인 정보와 비밀값이 없는지 확인
- 결과 확인: 날짜별 언어마다 `<언어>.md`가 최대 한 건이다. `run-summary.json`의 `language`, `generated`(0 또는 1), 발견·중복 제거 건수, 출처별 상태와 일치하는지 점검
- 디스크 관리: 결과 보존 정책을 정하고 용량을 정기 점검한다. 기본 동작은 자동 삭제하지 않는다.
- API 비용: 출처별 기사 수와 전체 입력 길이, 생성 토큰 상한을 설정하고 일일 통합 생성 요청 수를 관찰한다.

## 6. 장애 대응

| 증상 | 확인 사항 | 조치 |
|---|---|---|
| 설정 오류로 즉시 종료 | 필수 환경변수명, `.env` 경로, JSON 문법 | `.env.example`과 설정 표를 대조하고 비밀값을 로그/티켓에 복사하지 않는다. |
| 모든 출처에서 뉴스 0건 | URL, RSS/API 제공 여부, HTTP 상태, 사이트 구조 변경 | 해당 출처의 공개 피드/API와 접근 정책을 확인하고 수집기 설정을 갱신한다. |
| 한 출처만 반복 실패 | 해당 사이트의 HTTP 상태, 피드 URL 변경, 요청 제한 | 재시도 폭주를 피하고 해당 출처만 점검한다. 필요하면 일시적으로 출처를 설정에서 제외한다. |
| LLM HTTP 401 | API 키의 제공자, 유효 기간, 폐기 여부 | 키가 현재 설정한 제공자에서 발급됐는지 확인한다. 키를 로그나 지원 요청에 복사하지 않는다. |
| LLM HTTP 403 | 제공자 응답의 안전한 JSON 오류 코드/메시지, 프로젝트·조직 권한, 모델 접근 권한 및 계정 상태 | `LLM_BASE_URL`과 `LLM_MODEL`이 같은 제공자 설정인지 확인한다. 오류 세부 정보는 API 키 문자열을 마스킹한 뒤 출력한다. |
| LLM HTTP 404 | 기본 URL의 `/v1` 경로, Chat Completions endpoint 지원 여부 | 제공자의 OpenAI 호환 endpoint 경로를 확인한다. |
| LLM 응답 형식 실패 | 모델별 응답 차이, 토큰 한도, 프롬프트 버전 | 응답 검증 오류를 확인하고 프롬프트/API 어댑터 회귀 테스트를 보강한다. |
| 결과가 중복 또는 덮어씀 | `--force`, 날짜, URL 정규화, 병렬 실행 여부 | 재실행 정책과 시간대를 확인하고 강제 실행 전 기존 결과를 보존한다. |
| 디스크 쓰기 실패 | 디스크 공간, 파일 권한, 파일 시스템 | 공간 및 권한 복구 후 재실행한다. 기존 결과를 임의 삭제하지 않는다. |

## 7. 보안 및 업데이트

- `.env` 권한은 실행 사용자만 읽도록 제한하고 백업에도 동일한 비밀 관리 기준을 적용한다.
- 로그 및 오류 보고서에 요청 헤더, API 키, 원문 전문을 포함하지 않는다.
- 의존성 업데이트는 자동 테스트 후 적용한다.
- 뉴스 사이트의 정책·접근 방식이 바뀌면 크롤링을 확장하기보다 공개 RSS/API 제공 여부와 사용 허용 범위를 먼저 확인한다.
