# 시스템 설계

## 1. 설계 원칙

- cron 진입점은 셸 스크립트로 두고, HTTP·파싱·정규화·LLM 호출은 필요한 범위에서 Python으로 구현한다.
- 제공자 중립성을 위해 LLM 호출은 설정 가능한 OpenAI 호환 HTTP API를 사용한다.
- 뉴스 수집, 콘텐츠 변환, LLM 생성, 파일 저장을 분리해 출처별 변경과 테스트를 국소화한다.
- 외부 뉴스나 LLM 응답은 신뢰할 수 없는 입력으로 취급한다.

## 2. 논리 구성요소

| 구성요소 | 책임 |
|---|---|
| `run.sh` | 프로젝트 루트에서 실행, Python 환경 선택, 종료 코드 전달 |
| CLI | 옵션 파싱, 설정 검증, 실행 날짜 결정, 종료 상태 결정 |
| 설정 로더 | `.env`와 기본값을 읽고 타입·필수값 검증 |
| Source Registry | 설정된 각 미디어 URL에 적합한 수집기를 선택 |
| Collector | RSS/Atom 직접 URL 또는 페이지가 공개한 RSS/Atom 대체 링크 탐색, 후보 메타데이터 반환 |
| Normalizer | URL 및 제목 정규화, 게시일·언어 메타데이터 정리, 중복 제거 |
| Feed Content Normalizer | 피드 설명의 HTML 제거, 메타데이터 정리, 입력 총량 및 뉴스별 길이 제한 적용 |
| Daily Lesson Generator | 당일 뉴스 묶음을 프롬프트에 전달해 통합 다이제스트 1건 생성, 분량·응답 검증 및 제한된 재시도 |
| Renderer/Writer | 날짜별 단일 Markdown과 실행 요약을 원자적으로 기록 |
| Logger | 표준 오류에 진행·진단 로그 출력, 비밀값 마스킹 |

## 3. 처리 흐름

1. CLI가 `.env`, 명령행 옵션 및 날짜/시간대 설정을 읽는다.
2. 필수값, URL 스킴, 언어·수준, 쓰기 권한을 사전 검증한다. 잘못된 설정이면 네트워크 호출 전에 종료한다.
3. 설정된 각 미디어에서 공개 뉴스 후보를 수집한다. 기사 수 제한과 HTTP 타임아웃을 적용한다.
4. URL 정규화와 제목 유사도 키로 중복 후보를 제거한다. 동일 뉴스가 여러 매체에 보도된 경우 출처별 관점·추가 정보를 보존한다.
5. 성공적으로 수집된 뉴스 메타데이터 및 허용된 본문 발췌를 하나의 날짜별 뉴스 묶음으로 구성해 목표 언어·수준과 함께 프롬프트에 넣는다. 출처별 기사 수와 총 입력 길이를 제한한다.
6. OpenAI 호환 API를 한 번 호출해 전체 뉴스를 아우르는 일일 학습자료 1건을 만들고, 응답 섹션과 목표 분량을 검증한다.
7. 유효한 결과를 `result/YYYY-MM-DD/<language>.md`에 임시 파일로 쓴 뒤 rename하여 해당 언어의 완료된 파일만 노출한다.
8. 출처별 수집 성공·실패·발견 건수와 생성 문서(0 또는 1건), 오류 요약을 `run-summary.json`에 기록하고 종료 코드를 반환한다.

수집된 뉴스가 서로 다른 주제를 다루면 짧은 다이제스트 안에서 핵심 항목을 구분해 제시한다. 관련성이 증명되지 않은 사안끼리 인과관계나 공통 서사를 만들어내지 않는다.

## 4. 오류 및 재시도

- 각 출처와 뉴스 항목의 수집은 독립적으로 처리한다. 일부 항목의 실패 때문에 나머지 수집을 중단하지 않는다.
- 일부 뉴스 수집에 실패해도 성공적으로 수집된 뉴스 묶음으로 한 건의 자료를 생성한다. 유효한 뉴스가 없으면 자료 생성 없이 요약만 남긴다.
- LLM 생성은 뉴스 묶음 전체에 대해 한 단위로 처리한다. 생성 실패 시 부분적인 기사별 자료로 대체하지 않는다.
- 연결 오류, HTTP 429, 일시적 5xx는 횟수 제한이 있는 지수 백오프 재시도 대상이다. `Retry-After`가 있으면 존중한다.
- 잘못된 API 키, 설정 오류, 지원하지 않는 응답 형식은 재시도하지 않고 실패로 기록한다.
- LLM 응답이 비어 있거나 규격을 위반하면 설정된 횟수만큼 재요청할 수 있다. 검증되지 않은 응답은 결과물로 저장하지 않는다.
- 결과 디렉터리 생성/쓰기 실패는 해당 실행의 치명 오류로 처리한다.
- 어떤 비밀값도 로그나 `run-summary.json`에 저장하지 않는다. 오류 메시지에는 URL 쿼리의 토큰 등 민감정보도 마스킹한다.

## 5. 중복 및 재실행

- URL은 fragment 제거, 기본 포트·불필요한 추적 파라미터 제거 등 보수적 규칙으로 정규화한다. 콘텐츠를 다른 기사로 오인할 수준의 공격적 정규화는 하지 않는다.
- 제목 유사도는 동일 실행 내 중복 후보 제거의 보조 수단이며 출처 URL을 우선 키로 사용한다.
- 일일 산출물은 날짜 폴더 안의 언어별 `<language>.md` 한 개다. 실행 요약은 `run-summary.json`으로 저장한다.
- 날짜 폴더에 해당 언어의 완료된 자료가 있을 때 기본 동작은 생성을 건너뛰고 요약에 기록하는 것이다. 강제 재생성은 명시적 `--force`만 허용한다.
- 재실행은 일일 문서 단위로 처리하며 기사별 완료 파일을 따로 보존·생성하지 않는다.

## 6. 데이터 보관 및 콘텐츠 취급

- 영구 저장 대상은 생성 학습자료와 최소 실행 요약이다. 원문 전체를 기본 저장하지 않는다.
- 일일 학습자료에는 생성일, 학습 언어·수준, 다이제스트에 인용한 매체명과 원문 URL을 포함한다.
- 입력으로 본문을 가져오더라도 필요한 범위로 제한하고 프롬프트에 전체 기사 복제를 금지하는 지침을 둔다.
- 사이트의 공식 피드/API, 이용약관, 접근 정책을 우선 확인한다. 접근 통제나 유료벽을 우회하지 않는다.

## 7. 제안 저장소 구조

```text
.
├── .env.example
├── .gitignore
├── run.sh
├── requirements.txt
├── prompts/
│   └── news_to_lesson.md
├── src/
│   └── teachme/
│       ├── cli.py
│       ├── config.py
│       ├── collectors.py
│       ├── lesson.py
│       ├── models.py
│       └── storage.py
├── tests/
│   └── test_pipeline.py
├── result/
└── doc/
```

구현은 위 구조를 기준으로 한다. 런타임은 Python 표준 라이브러리만 사용한다. `.env`, 가상환경, 캐시, 비밀값 및 결과물은 `.gitignore`에 포함한다. 수집은 RSS/Atom을 우선하며, 공개 피드가 없으면 공개 목록 HTML에서 같은 사이트의 주요 기사 링크를 선별해 본문 텍스트를 읽는 fallback을 사용한다.

## 8. 주요 설계 위험

- 뉴스 사이트의 RSS 제공 여부와 HTML 구조는 바뀔 수 있다. 일반 HTML fallback은 heading/article/main 및 대표 기사 class 신호를 사용하므로 사이트 구조에 따라 선택 결과가 달라질 수 있다. 접근 제한을 우회하지 않고 실패 시 출처별 오류를 기록한다.
- 서로 다른 OpenAI 호환 제공자는 모델별 파라미터나 응답 형식이 다를 수 있다. 공통 최소 API만 사용하고 제공자별 설정 확장은 별도 결정으로 둔다.
- LLM이 형식, 길이, 사실성을 보장하지 않을 수 있다. 필수 필드 검증과 출처 링크 보존을 수행하며 생성 자료는 원문 사실의 독립 검증을 대체하지 않는다.
