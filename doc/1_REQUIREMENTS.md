# 제품 요구사항 명세

## 1. 목적

매일 지정된 뉴스 미디어를 확인하고, 설정된 학습 언어와 난이도에 맞춘 읽기 학습자료를 LLM으로 생성해 날짜별 결과 디렉터리에 저장한다. 실행은 자동화할 수 있어야 하며, 실패 원인을 `--debug` 실행으로 조사할 수 있어야 한다.

## 2. 사용자 및 사용 시나리오

- 운영자는 `.env`에서 LLM 접속 정보와 뉴스 미디어 URL을 관리하고, 실행 인자로 학습 언어를 지정한다.
- 운영자는 수동 명령 또는 cron으로 일일 작업을 실행한다.
- 학습자는 `result/YYYY-MM-DD/`에 생성된 Markdown 자료를 읽고 문제를 푼다.
- 운영자는 실패 시 디버그 로그와 출처별 처리 결과로 원인을 찾는다.

## 3. 범위

### MVP 포함

- `.env` 기반 설정 및 OpenAI 호환 Chat Completions API 호출
- 설정된 미디어 URL에서 공개 뉴스 항목 탐색. 공개 RSS/공식 API를 우선 사용하고, 필요하면 사이트별 공개 HTML 페이지를 제한적으로 처리
- 중복 뉴스 제거 및 당일 수집분 전체를 종합한 일일 학습자료 1건 생성
- 프롬프트 템플릿을 별도 파일에서 로드
- 학습 언어와 CEFR 수준은 각각 실행 시 `--language`, `--level`로 지정
- `result/YYYY-MM-DD/<언어>.md` 및 실행 요약 저장
- cron에 적합한 비대화형 셸 진입점, 종료 코드, 로그, `--debug`
- 개별 뉴스/출처 수집 실패가 나머지 뉴스 처리를 불필요하게 중단하지 않도록 하는 부분 성공 처리
- 읽기 본문은 250~350단어를 목표로 하고 어휘·질문을 포함한 전체 학습자료는 약 3~5분 안에 읽고 풀 수 있도록 제한

### MVP 제외

- 웹 UI, 사용자 계정, 데이터베이스, 장기 이력 검색
- 유료·로그인 전용 콘텐츠 접근, CAPTCHA 우회, 원문 전체 아카이빙
- 음성 합성, 플래시카드 앱, 사용자 진도 관리
- 복수 LLM 제공자별 전용 SDK 통합. OpenAI 호환 HTTP API를 기본 계약으로 한다.

## 4. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | 실행 시 필수 설정을 검증하고 누락·형식 오류를 사람이 이해할 수 있는 오류로 보고한다. | 필수 |
| FR-02 | 학습 언어와 목표 수준을 필수 `--language`, `--level` 실행 인자로 지정하고 뉴스 미디어 URL 목록은 `.env`로 설정할 수 있다. | 필수 |
| FR-03 | 기본 미디어는 영국 BBC와 Guardian, 미국 CNN과 AP, 프랑스 Le Monde, 벨기에 The Brussels Times다. | 필수 |
| FR-04 | 공개된 최신 뉴스 후보를 미디어별로 수집하고 출처 URL, 제목, 게시 시각을 보존한다. | 필수 |
| FR-05 | 같은 기사를 URL 정규화 및 제목 유사도 기반으로 중복 생성하지 않는다. | 필수 |
| FR-06 | 당일 수집·중복 제거된 뉴스 전체를 입력으로 사용해 프롬프트 파일을 통해 일일 학습자료를 정확히 1건 생성한다. | 필수 |
| FR-07 | 단일 자료에는 여러 뉴스의 핵심을 일관된 일일 다이제스트로 종합한 읽기 텍스트, 출처 링크, 어휘 및 이해도 점검을 포함한다. 서로 다른 사건을 근거 없이 하나의 이야기로 연결하지 않는다. | 필수 |
| FR-07a | Reading 본문은 250~350단어를 목표로 하고 전체 자료의 예상 학습 시간은 3~5분으로 제한한다. | 필수 |
| FR-08 | 결과를 실행 날짜 기준 `result/YYYY-MM-DD/<언어>.md`에 UTF-8 Markdown으로 기록한다. | 필수 |
| FR-09 | 하루 실행 결과에 발견·중복 제거·출처별 수집 성공/실패 및 학습자료 생성(0 또는 1건) 상태를 요약한다. | 필수 |
| FR-10 | `--debug`는 상세 로그와 예외 정보를 활성화하며 API 비밀값은 노출하지 않는다. | 필수 |
| FR-11 | 무인 실행에서 프롬프트 입력을 요구하지 않고 의미 있는 종료 코드를 반환한다. | 필수 |
| FR-12 | 동일 날짜의 재실행으로 기존 결과를 조용히 덮어쓰지 않는다. 재실행 동작은 설정 또는 명시적 옵션으로 통제한다. | 필수 |

## 5. 품질 요구사항

- **보안:** API 키는 `.env`에서 읽고 저장소에 커밋하지 않는다. 로그, 산출물, 예외 메시지에 키를 기록하지 않는다.
- **안정성:** HTTP 타임아웃과 제한된 재시도(지수 백오프)를 적용한다. 재시도 가능한 네트워크·서버 오류와 영구적인 설정·요청 오류를 구분한다.
- **콘텐츠 안전성:** 원문 접근은 공개적으로 허용된 경로에 한정한다. 접근 제한, robots 정책 또는 사이트 약관을 우회하지 않는다. 산출물은 교육 목적의 변형·요약으로 작성하고 원문 전체를 복제하지 않으며 출처를 표시한다.
- **재현성:** 실행 요약에 실행 시각, 설정된 언어·수준, 미디어, 처리 건수, 프롬프트 버전, 모델 식별자를 남긴다. 비밀값은 제외한다.
- **이식성:** 기본 운영 환경은 Linux와 POSIX 호환 셸로 한다. 필요한 경우 Python 런타임을 사용한다.
- **관측성:** 정상 실행은 간결한 로그, `--debug`는 단계별 상세 로그를 제공한다.

## 6. 수용 기준

1. `.env`를 설정하고 필수 `--language`, `--level`을 지정한 한 번의 명령으로 작업을 실행할 수 있다.
2. 실행마다 `--language`, `--level` 조합을 바꾸면 생성 언어·수준이 반영되고, 언어별 파일이 같은 날짜 폴더에 공존한다.
3. 설정된 각 출처의 처리 결과가 실행 요약에 집계된다.
4. 하나 이상의 뉴스가 수집되면 날짜 폴더에 전체 수집분을 반영한 단일 유효 Markdown 파일이 생성되며, 개별 뉴스 파일은 생성되지 않는다.
5. 생성 자료의 Reading은 250~350단어를 목표로 하고 어휘·질문을 포함한 전체 분량은 약 3~5분 학습량에 맞는다.
6. 수집 결과가 없거나 일부 출처가 실패해도 요약 및 종료 상태가 일관되게 기록된다. 모든 출처에서 수집 실패 시 자료는 생성하지 않는다.
7. `--debug` 실행은 진단에 충분한 상세 정보를 제공하되 API 키를 출력하지 않는다.
8. cron의 비대화형 환경에서 실행 가능하고 작업 실패 시 0이 아닌 종료 코드를 반환한다.

## 7. 결정 필요 항목 및 초기 제안

| 항목 | 초기 제안 | 확정 시점 |
|---|---|---|
| 학습 난이도 | 실행별 `--level` 필수, A1-C2 중 선택 | 제품 승인 |
| 기사 수 제한 | 출처별 최신 N건 설정, 초기값 3건 | MVP 부하 시험 전 |
| 날짜 및 시간대 | `TIMEZONE=UTC` 또는 운영자가 명시, 날짜 폴더는 이 시간대 기준 | 배포 전 |
| 재실행 정책 | 기본은 기존 파일 건너뜀, `--force`로 명시적 덮어쓰기 | CLI 구현 전 |
| 뉴스 발견 방식 | RSS/공식 API 우선, 사이트별 공개 페이지는 별도 어댑터 | 각 출처 연동 전 |
| 학습자료 형식 | 요약 텍스트, 어휘 설명, 이해 질문과 답안 | 프롬프트 확정 전 |
| 보존 정책 | 결과는 보관하고 자동 삭제하지 않음 | 운영 배포 전 |

## 8. 용어

- **미디어/출처:** 뉴스 항목을 발견하는 웹사이트 또는 RSS/API 엔드포인트.
- **뉴스 후보:** 메타데이터와 원문 URL을 수집했으나 아직 학습자료로 만들지 않은 항목.
- **일일 학습자료:** 당일 수집한 여러 뉴스의 주요 내용을 종합한 단일 학습 문서.
- **부분 성공:** 일부 뉴스 또는 출처가 실패했지만 수집된 뉴스로 일일 학습자료와 실행 요약이 생성된 상태.
